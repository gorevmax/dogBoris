# Plan.md: «Кто выгуливает Бориса» — micro-MVP

## 1. Текущий статус

- **Приоритет**: Учебный micro-MVP
- **Текущее состояние**:
  - "spec.md": источник продуктовых требований, контракт не меняется.
  - "PLAN.md": отражает фактический статус и результаты проверок.
  - "CLAUDE.md": постоянные правила агента.
  - "README.md": документирует запуск и границы текущего state.
- **Основная цель цикла**: убедиться, что главный сценарий из spec.md работает в реальном приложении на SQLite.
- **Обязательные ограничения**:
  - Только SQLite, без localStorage и моков.
  - Серверная атомарная блокировка занятых слотов.
  - Только синтетические данные.
  - Без авторизации, ролей, оповещений, деплоя.
  - Node.js + минимальный стек.
- **Основной контекст проекта**: учебный Node.js micro-MVP «Кто выгуливает Бориса» для компании «Догяндекс».
- **Текущий активный шаг**: подтверждение сценария и фиксация реального статуса.

## 1.1 Целевой сценарий

1. Сотрудник открывает общую страницу.
2. Видит текущую дату и пять фиксированных слотов прогулок.
3. Выбирает свободный слот.
4. Вводит ФИО.
5. Подтверждает запись.
6. Видит, что слот стал занятым и в нём отображается введённое ФИО.
7. Другой сотрудник пытается занять тот же слот и получает понятный отказ.
8. После обновления страницы или открытия приложения во втором браузере состояние остаётся тем же.
9. Сотрудник видит карточку «Последнее кормление» с ФИО и временем.
10. Сотрудник может отметить новое кормление — карточка обновляется.
