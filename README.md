\# Пёс Борис



Локальная страница компании ДогЯндекс для ведения учета кормления и прогулок пса Бориса



\## Назначение



Отслеживание регулярности прогулок и кормления пса Бориса, а также бронирование временных слотов для выгуливания пса


\## Файл настроек


В репозитории проекта создан файл secret.config, который предназначен для хранения такой настроечной информации, которая не может размещаться в публичном пространстве. Пока файл не содержит в себе критичной информации, он доступен для ознакомления пользователям репозитория. По ходу развития проекта и размещения в нем секреток, его необходимо будет передавать иным способом.



\## Локальный запуск



Запустите сервер командой `npm start` и откройте http://localhost:3000. Проверка синтаксиса выполняется командой `npm run build`.



\## Ограничения



Сайт сохраняет один самодостаточный `index.html` со встроенными HTML, CSS и JavaScript. `server.js` использует только встроенные `node:http`, `node:fs` и `node:path`, запоминает введенные значения и использует базу данных SQLLite, не использует внешние запросы. Регистрации, авторизация, роли пользователей, личные кабинеты отсутствуют;



\## Готовность



\- Сервер запускается на http://localhost:3000 без установки пакетов.

\- Видны шапка, текущая дата, пять слотов прогулок, свободные и занятые слоты различаются, а у занятого слота видно ФИО.

\- Слоты и их состояния бронирования загружаются через `GET /api/timeslots` и содержат пять слотов на текущую дату.

\- Визуально применен тёплый светло-фиолетовый фон, нежно-оранжевый основной цвет и крупная графика.

\- Бронирование слота отправляется через `POST /api/reservation`, выделяет забронированный слот и показывает подтверждение и ФИО забронировавшего.



\## Дальнейшие действия

\- Внесите ФИО сотрудника в любой свободный слот для выгуливания Бориса и нажмите кнопку "Записаться". Система переведет слот в занятое состояние и покажет ФИО сотрудника, который занял этот слот.

\- Внесите ФИО сотрудника на карточку последнего кормления. Убедитесь, что система зафиксировала дату, время последнего кормления и ФИО сотрудника, который покормил пса.

Эти два действия покажут функциональную работоспособность сервиса.



\## Следующий инженерный шаг - сборка приложения в контейнер

Сборка приложения в контейнер позволит сделать так, что приложение будет запускаться на других компьютерах, серверах независимо от версий библиотек, настроек системы, переменных окружения, наличия или отсутствия необходимого ПО на новом железе. Контейнер зафиксирует код, зависимости, переменные окружения, конфигурации в единый изолированный пакет. Таким образом, мое приложение для учета кормления и прогулок пса Бориса можно будет развернуть на серверах компании Догяндекс без проведения дополнительных работ по настройке. 

Далее, если в процессе эксплуатации моего приложения случатся нештатные ситуации (системный сбой или утечка памяти), то это не окажет влияния на другие контейнеры и операционную систему самого сервера.

Если мне нужно будет вносить изменения в функциональность сервиса, то я смогу проводить сборку, тестирование, деплой приложения в одинаковой среде разработки и развертывания, что ускорит проведение релизов и снизит риски ошибок.
